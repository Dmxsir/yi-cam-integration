## Phase 6C.6 policy decision

Do not auto-start every discovered camera.

Runtime state is explicit durable intent:

- HTTP `start` persists `desired_running=true`.
- HTTP `restart` persists `desired_running=true`.
- HTTP `stop` removes running intent.
- Newly discovered cameras default to stopped.
- Reprobe temporary stop/resume must not alter persisted intent.
- After backend/App restart, only persisted running cameras are restored.

This avoids unexpectedly opening all camera sessions while still enabling zero-manual-recovery after App restart.

When `yi_addon_service.py --data-dir <path>` is used:

## New implementation

### `yi_runtime_policy.py`

- Schema version 1.
- Persists only stable IDs that should run.
- No UID/DID/password/token/license/InitString data.
- Atomic temp-file + fsync + replace.
- Mode 0600 policy file; parent mode 0700 where supported.

### `yi_persistent_backend.py`

Persistence adapter around the already-proven `YiAddonBackend`.

- Persists runtime intent before start/stop/restart operations.
- Successful discovery reconciles desired IDs with discovered IDs.
- Missing/unavailable desired cameras remain pending.
- Health exposes safe runtime-persistence diagnostics:
  - desired running count
  - pending restore count
  - last reconcile timestamp
  - restored/failed counts
  - safe persistence error
- Camera/status output adds `persisted_desired_running`.
- Reprobe still uses direct lifecycle temporary isolation and does not change persisted intent.

### `yi_addon_service.py`

New options/behavior:

- `--data-dir` enables persistent backend layout.
- `--discovery-retry-interval` default 30 seconds.
- Initial cloud discovery failure keeps service alive.
- Persisted intent remains pending.
- Background retry continues until initial discovery succeeds.
- First successful later discovery uses normal reconcile and restores desired runtimes.

### Regression tests

`tests/test_yi_runtime_policy.py` covers:

- policy round trip
- mode 0600
- explicit stop removes intent
- unavailable desired camera remains pending
- simulated cloud discovery transport failure does not clear pending intent
