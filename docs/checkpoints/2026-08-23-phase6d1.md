## Local bundle path-gate correction

The first Local App bundle attempt stopped after the secret scan with:

```text
ERROR: development-machine path leaked into Local App package
```

This was a validation false positive, not an actual host-path leak. The staged `yi_runtime_lifecycle.py` retains a repo-relative development fallback `project_root/.analysis/phase3/bionic-root` for legacy development callers. The Home Assistant App never selects that fallback: `/run.sh` explicitly sets `RUNTIME_ROOT=/opt/yi-home/runtime/bionic-root` and passes both `--runtime-root` and the packaged `--worker-dir` to the backend.

The Local App bundle gate was corrected to:

- reject actual absolute development-host paths (`~/Documents`, `/home/<user>/Documents`) across packaged App source/config;
- reject `.analysis` in the real App startup files (`Dockerfile`, `run.sh`);
- require `/run.sh` to select `/opt/yi-home/runtime/bionic-root` explicitly;
- require the packaged Phase 3G worker directory to be passed explicitly.

No media/runtime implementation was changed for this correction.

## HA OS Local App gate

Home Assistant's current Local App testing guidance supports copying an App directory to a subdirectory of `/addons` on a real HA OS machine using Samba or SSH. A local App must not set `image:` when the intent is for Supervisor to build the local Dockerfile.

The project therefore stages a self-contained `yi_home/` directory with its generated `rootfs` and no development credentials. The Local App gate will prove, in order:

1. Supervisor detects the local `YI Home` App.
2. Supervisor builds the amd64 image from the same Dockerfile that passed the laptop image gate.
3. App starts with an empty restrictive `/data/yi.env` before YI account setup.
4. `/api/v1/health` becomes ready inside the App.
5. `/data/backend-api-token` is created and persists mode 0600 across App restart.
6. Supervisor discovery is attempted without exposing YI credentials.
7. No camera runtime is auto-started merely because cameras exist.
8. AppArmor issues, if any, are changed only from concrete HA OS audit evidence.

The Local App bundle utility regenerates the proven rootfs first and refuses to package known credential/state files.
